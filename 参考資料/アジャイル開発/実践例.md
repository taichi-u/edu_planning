# 研究ロードマップでの実践例

以下は、日付編集を題材にした架空の1週間である。数値と観察は説明用の仮データ。実際の機能変更や利用者調査の記録とは区別する。[調査本文](README.md) ／ [研究ロードマップの設計](../../docs/design/decisions.md)

## 1. 最初に何を確かめるか

**利用者の目的**は、学会の準備を1週間早めたあとも、提出先が定めた正式締切を確認できること。最初の問いを「準備開始日を変更したあと、利用者はいつ着手し、いつまでに提出するかを正しく説明できるか」とする。日付の追加や一括編集は、この問いを確かめたあとに順序を決める。[日付の運用方針](../../docs/integrations.md)

| 決めること | この例での内容 |
| --- | --- |
| 1週間で試せる範囲 | 仮の学会1件について、準備開始日を変更し、保存して開き直すところまでを扱う。 |
| この機能の受入条件 | 準備開始日を6月10日から6月3日に変更して開き直すと、準備開始日は6月3日、正式締切は6月30日と表示される。 |
| 各変更に共通の完成の定義 | 別の人が変更をレビューし、自動テストが通り、仮データで保存・再読込・権限の境界を確認し、利用者が試せる状態に統合する。 |
| 利用者に頼むこと | 日付を変更してもらい、次にいつ着手するか、正式締切はいつかを、作り手が答えを示す前に説明してもらう。 |

「準備開始日だけを更新できる」は機能固有の受入条件である。「レビューと検証を済ませ、統合された状態で使える」は他の変更にも適用する完成の定義である。この二つを記録しておくと、技術的な完成を確認したあとも利用者の反応に基づいて次の改善を選べる。[スクラムガイド](文献案内.md#g2)

## 2. 進行中に作業順を変える場面

月曜に日付更新の実装に着手する。火曜にレビュー依頼を出し、水曜も返答待ちであれば、作業は引き続き仕掛かりに含まれる。仮にチームが仕掛かり上限を2件とし、ほかに1件が検証中なら、その時点で上限に達している。次の機能を始める前に、誰が日付の保存処理を確認できるかを調整する。レビュー用データを準備すれば確認者が判断できるなら、その準備を引き取る。[Kanban Guide](文献案内.md#g3)

自動テストでは、保存後の準備開始日と正式締切を両方照合する。準備開始日の値だけを検査すると、正式締切まで連動して動く回帰を見逃す。統合時にこのテストを実行し、失敗時には日付の更新処理を特定して修正する。[CIの解説](文献案内.md#g5)

## 3. 同じ週のレビューと振り返り

| 場面 | 仮の観察 | 次の判断 |
| --- | --- | --- |
| 利用者と行う成果のレビュー | 3人とも保存できたが、1人は6月3日を「提出する日」と説明した。保存値は正しかった。 | 次回は一覧から詳細までの日付ラベルを確認する。一括編集を追加する前に、同じ操作で取り違えが起きる箇所を特定する。 |
| チームで行う進め方の振り返り | 月曜着手、木曜完了。仮に着手から完了まで72時間、うちレビュー待ちが48時間。 | 次回は着手時に確認者を決める。同じ規模の数件でレビュー待ち時間を記録し、待ちが他の工程へ移ったかも確かめる。 |

最初の観察は、どのラベルを再検討するかを決める材料になる。3人の結果から利用者全体の誤操作率を推定することはできない。二つ目の観察も1件の経過時間である。次の数件で対象の大きさ、休日、確認者の在席状況を併記すると、運用変更が効いた可能性を検討しやすい。[スクラムガイド](文献案内.md#g2) ／ [Kanban Guide](文献案内.md#g3)

## 4. 次の作業へ残す記録

| 項目 | 記入例 |
| --- | --- |
| 完了条件と実施結果 | 準備開始日だけ更新できた。再読込後の正式締切を自動テストと操作の両方で確認した。 |
| フィードバック | 一覧では準備開始日を正式締切と解釈した人がいた。 |
| 進行上の課題 | レビュー担当が決まるまで待ちが発生した。 |
| 次の変更案と確認方法 | 日付ラベルの理解を次の操作確認で調べる。担当者を先に決めた場合の待ち時間を記録する。 |

このリポジトリでは作業記録と変更案を区別し、採用した案だけを計画に反映する。研究活動そのものに応用する場合は、論文の節案、再現できる分析結果、指導時に判断できる比較表などを各回の成果物に置ける。ただし、ソフトウェアチームを対象とした研究結果を、研究成果や論文採択の予測に直接転用する根拠は今回の資料に含まれない。[運用方針](../../docs/integrations.md) ／ [研究の対象と限界](文献案内.md)
