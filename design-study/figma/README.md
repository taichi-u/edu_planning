# Figmaとの対応

- File: https://www.figma.com/design/ouepD2OumzSdZIQOmvc84O
- Session: この制作の編集可能な比較画面。実計画・認証情報は含めない。
- 共通の正本データ: ../fixture.json
- 比較案の色・書体: ../themes.mjs
- 画面構造: ../scene.mjs
- Code Connect: 対象ファイルなし。
- 既存画面: 作成時は空。ローカルのコンポーネント・変数・文字スタイルなし。
- 利用可能なライブラリ: Simple Design System等。Button・Table・色・文字スタイルを検索済み。
- 再利用の判断: 比較対象は既存のSaaSキットの外観ではなく、3方向の独自の時間軸・作業行・日本語組版。専用の色役割と日英の書体を持つ小規模なローカル部品を作る。既存ライブラリの近似を製品仕様の正本にはしない。
- スコープ: 比較画面18、共通のボタン・作業行・凡例・時間軸、配色・書体・状態見本。完全な汎用デザインシステムは作らない。
- Figmaの原始色と意味別の色を分け、各部品を変数と文字スタイルに結び付ける。反復する部品はインスタンスにする。
- 画像で画面全体を貼り付けない。画面は編集可能なテキスト・部品・ベクトル図形で作る。
- 案選定前の状態は「比較案」。採用済みと表示しない。

本人の回答後に作成した案1の修正版（`../revised.html`）も未反映。8画面を修正版として数えない。次回は最新の案1と初稿の差を確認し、採用された構造で更新する。

## 再開

`node design-study/figma/prepare.mjs view 8`で既存の枠へ配置するPlugin APIコードを出力できる。実行前にFigmaの該当スキルを読み、ファイル・ページ・ノードの存在を確認する。9–17も同じ手順。作成済みの0–7は差分を確認して更新する。

`foundations`は新規ファイル用。既存ファイルに再実行すると枠や変数が重複するので、再開には使わない。`build-view.js`と`foundations.js`はFigma実行環境向けのテンプレートで、Nodeの直接実行用ではない。
